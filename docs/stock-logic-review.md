## 4. 승률 신뢰도를 훼손하는 문제와 우선순위

### P0 — 데이터 품질과 실패 가시성

국가별 종목과 지수는 다른 거래일을 사용하므로 최대 날짜 하나로 최신성을 표현하면 안 된다. Yahoo 응답의 거래소/심볼도 검사해 .KS/.KQ 매핑을 확정한다.

### P0 — 과거와 현재의 진입 규칙 통일

### P0 — 과최적화와 실전 체결

[FACT] 종목별로 최대 13종류 신호와 8개 기간을 평가하고 같은 자료로 최고 EV를 선택한다. 계절성도 24조합 중 최고를 고른다. 별도 검증기간이 없다. 현재 살아 있는 S&P500 구성종목과 큐레이션 종목의 과거를 분석하므로 생존/선정 편향이 있다.

[RECOMMENDATION] 시간순 학습→검증→최종평가를 분리하고 워크포워드 검증을 시행한다. 가장 긴 보유기간에 따른 수익 라벨이 경계를 넘지 않게 겹친 표본을 제거한다. 개발자가 반복 확인하지 않은 최종 구간을 남기고 시도한 모든 규칙을 기록한다. 단순 분할만으로 반복적인 모델 선택 위험이 해소되지는 않는다. [Bailey 등의 원논문](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)도 투자 백테스트에서 전략 선택으로 생기는 과최적화를 다룬다.

종가로 신호 확정 후 다음 거래일 시가나 명시된 주문 방식으로 진입한다. 수수료·시장별 세금·스프레드·슬리피지와 거래정지/체결불가를 반영한다. 종목당 포지션 수, 자본, 동시 보유 제한을 정하고 중복 사건을 실제 거래와 구분한다. 현재 계산은 신호 후 수익 통계이지 자금 배분을 포함한 포트폴리오 수익률이 아니다.

### P1 — EV, 표본, 위험 지표

[FACT] EV = 승률×(평균이익/평균손실)−패배확률. 이는 수익률이 아닌 평균손실로 정규화한 점수다. 평균손실이 없으면 손익비를 99로 대입한다. 재현 테스트에서 전승 사례의 EV는 99가 됐다. 최소 20회는 단순 건수이며 가중치와 겹치는 수익구간의 독립성을 고려하지 않는다.

[RECOMMENDATION] 기대수익률 = 승률×평균이익−패배확률×평균손실을 비용 차감 후 표시한다. 손실 미관측은 손익비 추정 불가로 표시한다. 유효표본수 (Σw)²/Σw², 독립 사건 수, 블록 부트스트랩 신뢰구간, 연도/국가/시장상태별 성과를 제시한다. CAGR·MDD·Sharpe·Sortino·Profit Factor·회전율은 포트폴리오 시뮬레이션 이후 산출한다. 긴 보유기간은 동일기간 지수와 비교해 시장 상승의 효과를 분리한다.

### P1 — 계절성 달력

[FACT] 월일 대신 연중 일수를 사용해 윤년 정렬이 어긋날 수 있다. 상장 첫해의 첫 데이터가 지정일보다 훨씬 늦어도 해당 연도 진입으로 들어갈 수 있다. 연말에서 다음 해로 넘어가는 시작일도 단순 순환 숫자로 처리한다. 오늘 이미 지난 시작일의 과거 성과를 오늘 매수 기대치처럼 보여줄 수 있다.

[RECOMMENDATION] 거래소 달력과 월일로 진입일을 정하고 불완전 연도는 제외한다. 향후 진입 예정과 이미 지난 진입을 구분한다. 연도별 표본과 독립 평가 결과를 보여주고 다중탐색을 보정한다. 10년 중 8승은 안정적인 미래 80% 승률을 입증하지 않는다.

## 5. 실제 성과를 개선하기 위한 실험

[RECOMMENDATION] 아래는 효과가 확정된 처방이 아니라 독립 검증할 가설이다. 하나씩 추가하고 기존 전략과 같은 기간·비용·자본으로 비교한다.

1. 거래대금·스프레드·최소 가격 필터: 체결 가능성이 낮은 종목 제거.
2. 돌파 거래량/거래대금 증가: 거래량을 수집한 뒤 검증. 무조건 2배 같은 임계값을 먼저 최적화하지 않는다.
3. ATR 기반 구간·포지션 크기: 고정 -2/+3%, +5%가 종목 변동성을 무시하는 문제 개선.
4. 지수/섹터 대비 상대강도와 시장 레짐: 적용/미적용 성과를 국가별 비교. 현재 미국 중심 가이드가 다른 국가 성과에도 맞는지 확인.
5. 실적발표·공시 일정: 단기 전략의 이벤트 위험을 표시하고 회피 규칙을 실험.
6. 손절/시간청산/추적청산: 승률뿐 아니라 기대수익과 꼬리 손실을 함께 비교. 같은 일봉에서 손절·목표가가 모두 닿으면 보수적인 체결 순서 적용.
7. 섹터·상관관계·종목 비중 한도: 강한 한 섹터의 신호를 여러 개 사는 집중 위험 제한.

AI는 첫 단계에서 필요하지 않다. 데이터 QA·공시 분류·추천 이유 설명에는 활용 가치가 있지만, 숫자 점수 모델보다 유리한지 독립 평가한 뒤 도입한다. 가격 성과를 LLM 설명의 설득력으로 대체하지 않는다.

### 국가별 종목 마스터

- 한국: KOSPI·KOSDAQ 전체 마스터와 시장 구분을 로드하고 거래대금/거래정지/상장기간으로 분석 대상을 정의한다. [KRX 공식 OPEN API](https://openapi.krx.co.kr/)를 우선 검토한다. 이 조사에서는 구체적인 사용 승인·요금·호출 제한까지 확인하지 않았으므로 계약/권한 검토가 필요하다.
- 미국: S&P500 외 거래소 상장 보통주를 단계적으로 확대한다. ETF·ADR·우선주를 구분하고 종목 변경/상장폐지 이력을 관리한다. [Alpaca 공식 자료](https://alpaca.markets/learn/fetch-historical-data)는 다중 심볼 요청, 페이지네이션, split/dividend/all 조정을 설명한다. 실제 이용 범위와 공급 피드/플랜 조건은 도입 시 확인한다.
- 일본: [JPX 공식 상장종목 목록](https://www.jpx.co.jp/english/markets/statistics-equities/misc/01.html)을 활용해 큐레이션에서 전체 시장으로 확대한다. 이는 종목 목록이고 과거 일봉 공급과는 별도로 설계해야 한다.

현재 분석 성공 종목만으로 RS·시장폭을 계산하므로 누락이 섹터별로 다르면 결과도 바뀐다. 전 종목 마스터 기준 성공률을 국가·거래소·섹터별로 표시해야 한다. 넓어진 유니버스에서는 선택 시도도 늘어나므로 검증과 유동성 필터를 함께 강화한다.

### 수집·계산 구조

[FACT] 매일 전 종목의 최대 이력을 다시 받는다. ATH 계산은 각 날짜마다 이전 전체를 순회해 종목별 O(N²)이다. 252일 고점도 반복 순회하며 여러 이동평균의 통계를 다시 계산한다.

[RECOMMENDATION] 최초 전체 이력 적재 후 거래일 단위 증분 수집, 기업행위 시 해당 이력 재조정, 원본 보존, 실패 종목만 재수집을 구현한다. 다중 종목 요청과 공급자별 호출 한도/429 backoff를 적용한다. 동시성만 늘리는 방식은 실패율을 높일 수 있다. 응답 본문까지 타임아웃을 적용하고 실패 후 타이머도 정리한다.

ATH는 누적 최대값으로 O(N), rolling high/low는 deque, 이동평균은 한 번 계산해 재사용한다. 이력이 길고 종목이 많을수록 효과가 크다. 실행 시간은 계측 후 평가한다.

MVP는 별도 대형 플랫폼 없이 수집/정규화/신호/검증/출력 모듈과 버전 기록으로 충분하다. 원본·종목 마스터·신호/평가 결과를 분리하고 UI용 요약과 선택 종목 상세 파일을 나눠 초기 JSON을 줄인다. GitHub Actions는 오케스트레이션에 유지하고 캐시/원본은 적절한 영속 저장소에 보존한다.

## 7. 실행 순서와 완료 기준

1. 데이터 QA: 누락 원인·국가별 기준일·지수 상태 확인, 이상값과 수정주가 검증. 실패 자료가 최신 추천으로 발행되지 않을 것.
2. 공통 신호 엔진: 역사/현재의 진입 조건 완전 일치, 박스폭 누락과 이벤트 중복 수정. 사건별 결과를 재현 가능하게 기록할 것.
3. 실행 백테스터: 다음 거래일 진입, 비용, 자본/포지션 제약. 시장 대비 순수익과 낙폭을 계산할 것.
4. 워크포워드 평가: 독립 기간 성과·유효표본·신뢰구간·다중선택 이력 공개. 임의의 목표 승률 대신 기존 전략 대비 개선 여부를 확인할 것.
5. 확대: 기존 누락 복구 후 한국/미국/일본 마스터를 단계적으로 확대. 국가별 수집 성공률·최신성·런타임·유동성을 함께 측정할 것.
6. 운영 자산화: 신호 ID, 전략/데이터 버전, 발생 당시 입력, 실제 추적 수익을 쌓는다. 장기적으로 차별화할 자산은 지표 수보다 검증 가능한 추천 이력과 데이터 품질이다.

## 8. 확인 방법과 한계

[FACT] 소스 정적 검토, 저장 JSON 집계, 독립 리뷰, node --check, 핵심 함수의 격리 재현 테스트를 수행했다. docs/audit-stock-logic.mjs를 실행하면 주요 수치와 전승 EV 사례를 다시 확인할 수 있다. 네트워크 수집 전체 실행과 실전 성과 재백테스트는 수행하지 않았다. --selftest는 합성 데이터로 기존 data.json을 덮어쓰므로 실행하지 않았다.

현재 파일에는 전체 원본 시계열·종목별 날짜·실패 이력·포지션 이력이 없다. 따라서 실제 승률, 비용 차감 기대수익, 데이터 누락 원인과 개선 후 승률 상승 폭은 확정할 수 없다. 운영 소스와 data.json은 수정하지 않았다.
